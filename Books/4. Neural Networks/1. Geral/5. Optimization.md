# Deep Learning Optimization

## 1. Forward, Backward and Residual Connections

### 1.1 Forward Pass — signal propagation

At each layer, the signal (activation) is transformed:

```
x → Linear → Activation → x'
```

In deep networks without residual connections, the signal can distort or weaken progressively layer by layer.

### 1.2 Backward Pass — gradient propagation

The loss gradient flows back through the network via the chain rule:

```
∂L/∂x = ∂L/∂y · ∂y/∂x
```

At each layer, the gradient is multiplied by the local derivative. If those derivatives are small (< 1), the gradient **attenuates progressively** — by the time it reaches the early layers it's nearly zero and they stop learning. This is **vanishing gradient**.

### 1.3 Residual Connection

Adds a direct path (skip) that bypasses the transformation:

```
y = F(x) + x
```

During backprop, the derivative becomes:

```
∂L/∂x = ∂L/∂y · (∂F(x)/∂x + 1)
```

The `+1` guarantees **there is always a path through which the gradient passes intact**, regardless of what `F(x)` learned. The gradient signal from the last layer maintains its strength in the early layers — no attenuation through the skip path.

This is what enables training much deeper networks (ResNet, Transformers use this everywhere).

## 2. Optimizers

All optimizers share the same goal: **update weights to minimize the loss**. The difference is *how* they use the gradient.

### 2.1 Vanilla SGD

```
θ = θ - lr · ∇L
```

Simple and direct. Problems: slow in flat regions, oscillates in ravines, sensitive to lr choice.

### 2.2 SGD + Momentum

```
v = β · v - lr · ∇L
θ = θ + v
```

Accumulates a "velocity" in the direction the gradient has been consistently pointing. This:
- Accelerates in consistent directions
- Dampens oscillations in inconsistent directions (ravines)

Typical `β`: `0.9`

### 2.3 RMSProp

```
s = β · s + (1 - β) · ∇L²
θ = θ - lr · ∇L / (√s + ε)
```

Keeps a running average of the squared gradients per parameter. Parameters with large gradients get a smaller effective lr — **per-parameter adaptive lr**.

Useful when different parameters have gradients at very different scales.

### 2.4 Adam (Adaptive Moment Estimation)

Combines momentum + RMSProp:

```
m = β₁ · m + (1 - β₁) · ∇L        # 1st moment (mean)
v = β₂ · v + (1 - β₂) · ∇L²       # 2nd moment (variance)

m̂ = m / (1 - β₁ᵗ)                  # bias correction
v̂ = v / (1 - β₂ᵗ)                  # bias correction

θ = θ - lr · m̂ / (√v̂ + ε)
```

Defaults: `β₁=0.9`, `β₂=0.999`, `ε=1e-8`

The standard optimizer for most tasks. Converges fast, stable, works well without heavy lr tuning.

### 2.5 AdamW

Adam with decoupled weight decay:

```
θ = θ - lr · m̂ / (√v̂ + ε) - lr · λ · θ
```

In vanilla Adam, weight decay and L2 regularization are not equivalent (because of the adaptive scaling). AdamW fixes this — current standard for LLMs and Transformers.

### Quick comparison

| Optimizer | Adaptive | Momentum | When to use |
|---|---|---|---|
| SGD | ✗ | ✗ | Simple baseline |
| SGD + Momentum | ✗ | ✓ | Classic CV (ResNets) |
| RMSProp | ✓ | ✗ | RNNs, RL |
| Adam | ✓ | ✓ | General default |
| AdamW | ✓ | ✓ | Transformers, LLMs |

## 3. LR Scheduler and Gradient Clipping

### 3.1 Learning Rate Scheduler

A fixed lr is rarely optimal throughout the entire training. Schedulers adjust lr over time.

**Step / MultiStep Decay**
```python
# lr *= γ every N epochs
scheduler = StepLR(optimizer, step_size=30, gamma=0.1)
```
Simple. Reduces lr at predefined checkpoints.

**Cosine Annealing**
```python
scheduler = CosineAnnealingLR(optimizer, T_max=100)
```
Smoothly decays following a cosine curve down to a minimum lr. Current standard for most training runs.

**Warmup + Decay**

Starts with a low lr, ramps up gradually, then decays:

```
lr = lr_max · min(step/warmup_steps, cosine_decay)
```

Essential for Transformers — a high lr at the start destabilizes the attention layers before they've had a chance to converge.

**ReduceLROnPlateau**
```python
scheduler = ReduceLROnPlateau(optimizer, patience=5, factor=0.5)
```
Reduces lr when a metric stops improving. Useful when you don't know upfront when to decay.

### 3.2 Gradient Clipping

Prevents **exploding gradients** — the opposite problem of vanishing. Happens especially in RNNs and early in Transformer training.

**Clip by norm** (most common):
```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

Scales the entire gradient if its global norm exceeds `max_norm`:

```
if ||g|| > max_norm:
    g = g · (max_norm / ||g||)
```

Gradient direction is preserved, only the magnitude is capped.

**Clip by value** (less common):
```python
torch.nn.utils.clip_grad_value_(model.parameters(), clip_value=0.5)
```

Clips each component individually — changes the gradient direction, which is why it's less recommended.

### Correct order in the training loop

```python
optimizer.zero_grad()
loss = model(x)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # before step
optimizer.step()
scheduler.step()
```

Clipping always **before** `optimizer.step()`, after `backward()`.
