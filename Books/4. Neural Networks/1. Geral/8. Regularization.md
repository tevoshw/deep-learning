# Regularization

Overfitting happens when **train loss drops but val loss rises** — the model memorizes training-specific patterns that don't generalize. Common causes: too little data, model too large for the data, or training too long.

Outliers and bad data are a separate problem — they cause the model to memorize the wrong things, but the root cause is data quality, not overfitting itself.

Regularization constrains the model during training to force generalization regardless of the cause. The core idea: prevent the network from relying too heavily on any specific weight or feature.

---

## L1 (Lasso)

Adds the sum of absolute values of weights to the loss:

```
loss = criterion(output, target) + λ * Σ|w|
```

```python
l1 = sum(p.abs().sum() for p in model.parameters())
loss = criterion(output, target) + lambda_ * l1
loss.backward()
```

The gradient of `|w|` is `±1` — constant regardless of weight magnitude. This pushes small weights all the way to zero, producing sparse models. Useful when you want implicit feature selection.

---

## L2 (Ridge / Weight Decay)

Adds the sum of squared weights to the loss:

```
loss = criterion(output, target) + λ * Σw²
```

```python
l2 = sum(p.pow(2).sum() for p in model.parameters())
loss = criterion(output, target) + lambda_ * l2
loss.backward()
```

The gradient of `w²` is `2w` — proportional to the weight. Large weights are pulled harder toward zero, small weights barely touched. Prefers distributed small weights over sparse ones.

In practice, use AdamW instead of adding L2 manually — they're not equivalent because Adam scales gradients by moment estimates, which distorts the L2 penalty:

```python
# L2 via loss: penalty passes through Adam scaling — distorted
# AdamW: decay applied directly on the weight, outside Adam
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4, weight_decay=0.01)
```

## Dropout

Randomly zeros a fraction `p` of activations after a layer during training:

```python
nn.Linear(128, 64),
nn.ReLU(),
nn.Dropout(p=0.5),
nn.Linear(64, 32),
```

Each forward pass gets a different random mask — the network never knows which features will be available. This forces redundancy: the same information gets distributed across multiple neurons instead of concentrated in one.

At inference, dropout is disabled (`model.eval()`). PyTorch uses inverted dropout during training — divides surviving activations by `(1-p)` — so no scaling is needed at inference.

Don't apply dropout on the output layer.

## Early Stopping

Stop training when validation loss stops improving:

```python
best_val_loss = float('inf')
patience = 10
counter = 0

for epoch in range(max_epochs):
    train(model)
    val_loss = evaluate(model)

    if val_loss < best_val_loss:
        best_val_loss = val_loss
        counter = 0
        torch.save(model.state_dict(), 'best.pt')
    else:
        counter += 1
        if counter >= patience:
            print(f'Stopping at epoch {epoch}')
            break

model.load_state_dict(torch.load('best.pt'))
```

`patience` defines how many epochs to wait before stopping. Always restore the best checkpoint after stopping — the last epoch is not the best one.

---

## Summary

| Technique | Where | Effect |
|---|---|---|
| L1 | Loss | Sparse weights, feature selection |
| L2 / Weight decay | Loss or AdamW | Small distributed weights |
| Dropout | Architecture (post-activation) | Redundant representations |
| Early stopping | Training loop | Stops before overfitting |
