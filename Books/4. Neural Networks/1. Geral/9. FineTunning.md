# Fine-Tuning Types

Fine-tuning is taking a pre-trained model and continuing training on specific data for a new task. Instead of training from scratch, you inherit learned representations and specialize them.

Early layers learn generic features. Later layers learn task-specific features. Fine-tuning reuses the generic ones and re-specializes the rest.

---

## 1. Freezing Weights

Control which parameters participate in training via `requires_grad`. The backprop simply skips frozen weights.

### Full Freeze (train only the head)

Freeze everything, unfreeze only the last layer. Use when your task is similar to the pre-trained one and you have little data.



### Partial Freeze (train specific layers)

Freeze early layers, train the rest. Use when your task is different enough that only re-specializing the head isn't sufficient.


Always inspect names before filtering. Verify after backward that frozen weights are truly frozen


---

## 2. LoRA / QLoRA

Instead of updating weights directly, injects trainable low-rank matrices into layers. The original weights stay frozen — only the adapters train. ~100x fewer parameters than full fine-tuning.

```
W' = W + A @ B
# W: original frozen weights (d x d)
# A, B: trainable adapters (d x r and r x d), where r << d
```

```python
from peft import get_peft_model, LoraConfig

config = LoraConfig(
    r=8,              # rank — lower = fewer params, less expressive
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"]
)

model = get_peft_model(model, config)
model.print_trainable_parameters()
# trainable params: 4,194,304 || all params: 6,742,609,920 || trainable: 0.06%
```

**QLoRA** adds 4-bit quantization — base model loaded in 4-bit, adapters train in bf16. Enables fine-tuning 70B models on a single consumer GPU.

```python
from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.bfloat16
)

model = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=bnb_config)
model = get_peft_model(model, lora_config)
```

LoRA is the default for LLM fine-tuning. QLoRA when hardware is limited.

---

## 3. RLHF — Reinforcement Learning from Human Feedback

Aligns LLMs to human preferences. Used in GPT-4, Claude, Gemini. Three stages:

**Stage 1 — SFT:** fine-tune on high-quality demonstrations first.

**Stage 2 — Reward Model:** humans rank model outputs (response A vs B). A reward model is trained to predict the human preference score.

**Stage 3 — RL optimization:** optimize the LLM against the reward model using PPO, with a KL divergence penalty to prevent drifting too far from the SFT model.

```
base model → SFT → reward model training → PPO optimization → aligned model
```

Expensive and complex. Requires significant infrastructure. In practice, **DPO replaced RLHF** in most open-source pipelines — same goal, no reward model, no RL loop, comparable results.

---

## When to Use What

| Scenario | Approach |
|---|---|
| Similar task, little data | Full freeze + train head |
| Different task, medium data | Partial freeze |
| Large model, limited hardware | LoRA or QLoRA |
| Align to human preferences (simple) | DPO |
| Align to human preferences (at scale) | RLHF |
