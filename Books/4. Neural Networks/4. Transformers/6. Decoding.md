# Decoding

Decoding is the process of transforming the logits (raw scores) that the model produces into the final text, token by token. It happens **after** the forward pass — the model doesn't choose a token, decoding does.

```
Forward pass -> logits (raw scores per vocab token)
Decoding     -> picks 1 token from those logits
```

---

## 1. Greedy

Always picks the index of the highest logit.


**Softmax is optional here.** Softmax is monotonic — it doesn't change the *order* of values, only rescales them into probabilities (sum = 1). Whoever had the biggest logit still has the biggest probability after softmax. So `argmax` gives the same result with or without it.

**Pros:** deterministic (same input -> same output always), fast, simple.
**Cons:** repetitive/looping text, no variation, short-sighted (never reconsiders past choices).

---

## 2. Temperature

Used together with **sampling** (see #4). Instead of always taking the max, tokens are drawn like a roulette wheel — softmax probabilities become each token's chance of being picked.

Problem: raw logits often produce a very "sharp" distribution (one token dominates ~100%), so the roulette rarely lands anywhere else. Temperature reshapes the distribution **before** softmax:


- `temperature < 1` → logits move **away** from each other (bigger magnitude) → softmax becomes sharper → closer to greedy
- `temperature > 1` → logits move **toward** 0 (smaller magnitude, closer together) → softmax becomes flatter → more uniform/random
- `temperature = 1` → no change (plain softmax)

```python
# lower temperature (0.5) -> logits grow apart
2.0 / 0.5 = 4.0
1.0 / 0.5 = 2.0
0.5 / 0.5 = 1.0

# higher temperature (2.0) -> logits shrink toward 0
2.0 / 2.0 = 1.0
1.0 / 2.0 = 0.5
0.5 / 2.0 = 0.25
```

**Why this matters:** softmax uses `e^x`, which amplifies differences. Values far apart → huge probability gap after exponentiation. Values close together (near 0) → exponentiation barely separates them → probabilities end up similar.

---

## 3. Top-k / Top-p

Both **cut the candidate pool** before sampling — instead of considering the entire vocabulary.

**Top-k**: keeps only the `k` highest-probability tokens, discards the rest, samples among those. Fixed number of candidates regardless of the model's confidence.


**Top-p (nucleus sampling)**: keeps the smallest set of tokens whose cumulative probability passes a threshold `p` (e.g. 0.9). Adaptive — few tokens when the model is confident, many when it's uncertain. Note: cumulative sum will often slightly *exceed* `p` (e.g. 0.91), since it stops at the first token that crosses the threshold — this is expected, not an error.

.
---

## 4. Sampling

The umbrella technique: draw the next token from a probability distribution (roulette wheel) instead of always taking the max. Performs the draw — each token's chance of being picked is proportional to its probability. The highest-probability token is *most likely* to win, but not guaranteed.

Temperature, top-k, and top-p are not alternatives to sampling — they're ways to **reshape the roulette wheel** before the draw happens. Sampling is always the final step.

---

## Compatibility

| Method | Combines with sampling? |
|---|---|
| Greedy | No — greedy never draws, so temperature/top-k/top-p have zero effect on it |
| Temperature | Yes |
| Top-k | Yes |
| Top-p | Yes |

Greedy is used alone. Temperature + top-p (sometimes + top-k) is the common production combo for conversational text generation.
